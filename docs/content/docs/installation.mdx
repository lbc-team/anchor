## 安装依赖包

- Windows 用户必须首先安装 WSL（Windows 子系统 Linux），然后安装以下 Linux 部分中指定的依赖包。
- Linux 用户应该首先安装以下 Linux 部分中指定的依赖包。
- Mac 用户应首先按照以下的 Rust 安装说明进行操作。

<Accordions>
  <Accordion title="Windows 子系统 Linux (WSL)">
    要在 Windows 上开发 Solana 程序，**您必须使用
    [WSL](https://learn.microsoft.com/en-us/windows/wsl/install)**（Windows 子系统 Linux）。所有额外的依赖项必须通过 Linux 终端安装。

    一旦安装了 WSL，请在继续安装 Rust、Solana CLI 和 Anchor CLI 之前，安装以下 Linux 部分中指定的依赖项。

    要安装 WSL，请在 Windows PowerShell 中运行以下命令：

    ```shell
    wsl --install
    ```

    安装过程将提示您创建一个默认用户帐户。

    ![WSL 安装](/docs/installation/wsl-install.png)

    默认情况下，WSL 安装 Ubuntu。您可以通过在搜索框中搜索 "Ubuntu" 打开 Linux 终端。

    ![WSL Ubuntu](/docs/installation/wsl-ubuntu-search.png)

    如果您的 Ubuntu 终端如下图所示，您可能会遇到 `ctrl + v`（粘贴快捷键）在终端中不起作用的问题。

    ![Ubuntu 终端](/docs/installation/wsl-ubuntu-terminal-1.png)

    如果遇到此问题，请通过在搜索框中搜索 "Terminal" 打开 Windows 终端。

    ![Windows 终端](/docs/installation/wsl-windows-terminal.png)

    接下来，关闭 Windows 终端并再次搜索 Ubuntu 以重新打开 Linux 终端。此时终端应如下图所示，`ctrl + v`（粘贴快捷键）可以正常使用。

    ![Ubuntu 终端](/docs/installation/wsl-ubuntu-terminal-2.png)

    如果您使用的是 VS Code， [WSL 扩展](https://code.visualstudio.com/docs/remote/wsl-tutorial) 可以让您将 WSL 和 VS Code 一起使用。

    ![在 VS Code 中设置 WSL](/docs/installation/wsl-vscode.png)

    然后您会在 VS Code 状态栏中看到以下内容：

    ![WSL: Ubuntu](/docs/installation/wsl-vscode-ubuntu.png)

    一旦设置完成 WSL，所有额外的依赖项必须通过 Linux 终端安装。在继续安装 Rust、Solana CLI 和 Anchor CLI 之前，安装以下 Linux 部分中指定的依赖项。

  </Accordion>
  <Accordion title="Linux">
    安装 Anchor CLI 所需以下依赖项。

    首先，运行以下命令：

    ```shell
    sudo apt-get update
    ```

    接下来，安装以下依赖项：

    ```shell
    sudo apt-get install -y \
        build-essential \
        pkg-config \
        libudev-dev llvm libclang-dev \
        protobuf-compiler libssl-dev
    ```

    如果在安装 `protobuf-compiler` 时遇到以下错误，请确保您首先运行 `sudo apt-get update`：

    ```
    包 protobuf-compiler 不可用，但被另一个包引用。
    这可能意味着该包缺失、已被淘汰或仅从其他来源可用。
    ```

  </Accordion>
</Accordions>

### 安装 Rust

Solana 程序是用
[Rust programming language](https://www.rust-lang.org/) 编写的。

推荐的 Rust 安装方法是
[rustup](https://www.rust-lang.org/tools/install)。

运行以下命令以安装 Rust：

```shell
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
```

安装完成后，您应看到以下消息：

<Accordions>
<Accordion title="成功安装 Rust 消息">

```
Rust 现在已安装。太好了！

要开始使用，您可能需要重新启动当前的 shell。
这将重新加载您的 PATH 环境变量以包含除 Cargo bin 目录 ($HOME/.cargo/bin) 外的所有内容。

要配置当前的 shell，您需要源代码
$HOME/.cargo 下相应的 env 文件。

通常通过运行以下命令之一来完成（注意前面的 DOT）：
. "$HOME/.cargo/env"            # 对于 sh/bash/zsh/ash/dash/pdksh
source "$HOME/.cargo/env.fish"  # 对于 fish
```

</Accordion>
</Accordions>

运行以下命令以重新加载您的 PATH 环境变量以包含 Cargo 的 bin 目录：

```shell
. "$HOME/.cargo/env"
```

要验证安装是否成功，请检查 Rust 版本：

```shell
rustc --version
```

您应看到类似于以下的输出：

```
rustc 1.80.1 (3f5fd8dd4 2024-08-06)
```

</Step>

### 安装 Solana CLI

Solana CLI 提供构建和部署 Solana 程序所需的所有工具。

使用官方安装命令安装 Solana CLI 工具套件：

```shell
sh -c "$(curl -sSfL https://release.anza.xyz/stable/install)"
```

您可以将 `stable` 替换为与您所需版本的软件发行版匹配的版本标签（例如 `v2.0.3`），或者使用以下三个符号通道名称中的一个：`stable`、`beta` 或 `edge`。

如果您第一次安装 Solana CLI，您可能会看到以下消息提示您添加 PATH 环境变量：

```
关闭并重新打开终端以应用 PATH 更改，或在现有 shell 中运行以下命令：

export PATH="/Users/test/.local/share/solana/install/active_release/bin:$PATH"
```

<Tabs groupId="language" items={['Linux', 'Mac']}>
<Tab value="Linux">

如果您使用的是 Linux 或 WSL 终端，您可以通过运行安装时记录的命令或重启终端将 PATH 环境变量添加到 shell 配置文件中。

```shell
export PATH="$HOME/.local/share/solana/install/active_release/bin:$PATH"
```

</Tab>
<Tab value="Mac">

如果您在 Mac 上使用 `zsh`，安装时记录的默认 `export PATH` 命令在关闭终端后不会保留。

相反，您可以通过运行以下命令将 PATH 添加到 shell 配置文件中：

```shell
echo 'export PATH="$HOME/.local/share/solana/install/active_release/bin:$PATH"' >> ~/.zshrc
```

然后运行以下命令以刷新终端会话，或重启终端。

```shell
source ~/.zshrc
```

</Tab>
</Tabs>

要验证安装是否成功，请检查 Solana CLI 版本：

```shell
solana --version
```

您应看到类似于以下的输出：

```
solana-cli 1.18.22 (src:9efdd74b; feat:4215500110, client:Agave)
```

您可以在 [Agave Github repo](https://github.com/anza-xyz/agave/releases) 查看所有可用版本。

<Callout>

Agave 是 [Anza](https://www.anza.xyz/) 的验证客户端，以前称为 Solana Labs 验证客户端。

</Callout>

要稍后将 Solana CLI 更新到最新版本，您可以使用以下命令：

```shell
agave-install update
```

</Step>

### 安装 Anchor CLI

Anchor 是一个用于开发 Solana 程序的框架。Anchor 框架利用 Rust 宏简化了编写 Solana 程序的过程。

安装 Anchor CLI 和工具有两种方式：

1. 使用 Anchor 版本管理器 (AVM) - 这是**推荐的安装**方法，因为它简化了将来 Anchor 版本的更新
2. 无 AVM - 这需要更多的手动过程来稍后更新 Anchor 版本

<Tabs groupId="anchor" items={['AVM', 'Without AVM']}>
<Tab value="AVM">

Anchor 版本管理器 (AVM) 允许您在系统上安装和管理不同的 Anchor 版本，包括更轻松地在将来更新 Anchor 版本。

使用以下命令安装 AVM：

```shell
cargo install --git https://github.com/coral-xyz/anchor avm --force
```

测试以确保 AVM 已成功安装并可访问：

```shell
avm --version
```

使用 AVM 安装最新版本的 Anchor CLI：

```shell
avm install latest
avm use latest
```

或通过声明您想要安装的版本来安装特定版本的 Anchor CLI：

```shell
avm install 0.30.1
avm use 0.30.1
```

> 请不要忘记运行 `avm use` 命令以声明系统上应该使用哪个 Anchor CLI 版本。
>
> - 如果您安装了 `latest` 版本，请运行 `avm use latest`。
> - 如果您安装了 `0.30.1` 版本，请运行 `avm use 0.30.1`。

</Tab>

<Tab value="Without AVM">

使用以下命令安装特定版本的 Anchor CLI：

```shell
cargo install --git https://github.com/coral-xyz/anchor --tag v0.30.1 anchor-cli
```

</Tab>
</Tabs>

在 Linux 或 WSL 上安装 Anchor CLI 时，您可能会遇到此错误：

```
error: could not exec the linker cc = note: Permission denied (os error 13)
```

如果您看到此错误消息，请遵循以下步骤：

1. 安装在此页面顶部列出的 Linux 部分中的依赖项。
2. 重试安装 Anchor CLI。

#### Node.js 和 Yarn

Node.js 和 Yarn 是运行使用 `anchor init` 命令创建的默认 Anchor 项目测试文件（TypeScript）所必需的。（Rust 测试模板也可以使用 `anchor init --test-template rust` 可用）

<Accordions>
<Accordion title="Node 安装">

安装节点的推荐方法是使用
[Node Version Manager (nvm)](https://github.com/nvm-sh/nvm)。

使用以下命令安装 nvm：

```shell
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/master/install.sh | bash
```

重启您的终端并验证 nvm 是否安装成功：

```shell
command -v nvm
```

接下来，使用 `nvm` 安装节点：

```shell
nvm install node
```

要验证安装是否成功，请检查 Node 版本：

```
node --version
```

您应看到类似于以下的输出：

```
v22.7.0
```

</Accordion>
<Accordion title="Yarn 安装">

安装 Yarn：

```shell
npm install --global yarn
```

要验证安装是否成功，请检查 Yarn 版本：

```
yarn --version
```

您应看到以下输出：

```
1.22.1
```

</Accordion>
</Accordions>

当运行 `anchor build` 时，如果您遇到类似于以下 "error: not a directory" 的错误：

```
error: not a directory: '.../solana-release/bin/sdk/sbf/dependencies/platform-tools/rust/lib'
```

请尝试以下解决方案：

1. 使用以下命令强制安装：

```shell
cargo build-sbf --force-tools-install
```

2. 如果上面的办法无效，请清除 Solana 缓存：

```shell
rm -rf ~/.cache/solana/*
```

应用其中任何解决方案后，请再次尝试运行 `anchor build`。

如果您在 Linux 或 WSL 上且创建新的 Anchor 项目后运行 `anchor test` 时遇到以下错误，可能是因缺失 Node.js 或 Yarn 所致：

```
Permission denied (os error 13)
```

```
No such file or directory (os error 2)
```

## Solana CLI 基础知识

本节将介绍一些常见的 Solana CLI 命令，以帮助您入门。

<Steps>
<Step>

### Solana 配置

要查看当前配置：

```shell
solana config get
```

您应看到类似于以下的输出：

```
配置文件: /Users/test/.config/solana/cli/config.yml
RPC URL: https://api.mainnet-beta.solana.com
WebSocket URL: wss://api.mainnet-beta.solana.com/ (计算得出)
Keypair 路径: /Users/test/.config/solana/id.json
承诺: 确认
```

RPC URL 和 Websocket URL 指定了 CLI 将请求的 Solana 集群。默认情况下将使用 mainnet-beta。

您可以使用以下命令更新 Solana CLI 集群：

```
solana config set --url mainnet-beta
solana config set --url devnet
solana config set --url localhost
solana config set --url testnet
```

您也可以使用以下短选项：

```
solana config set -um    # 适用于 mainnet-beta
solana config set -ud    # 适用于 devnet
solana config set -ul    # 适用于 localhost
solana config set -ut    # 适用于 testnet
```

Keypair 路径指定了 Solana CLI 用于支付交易费用和部署程序的默认钱包的位置。默认路径是
`~/.config/solana/id.json`。接下来的步骤将介绍如何在默认位置生成一个 keypair。

</Step>
<Step>

### 创建钱包

要使用 Solana CLI 与 Solana 网络进行交互，您需要一个资金充足的 Solana 钱包。

要在默认 Keypair 路径生成一个 keypair，请运行以下命令：

```shell
solana-keygen new
```

您应看到类似于以下的输出：

```
生成一个新的 keypair

为了增强安全性，请输入一个 BIP39 密码短语

注意！此密码短语仅提高恢复种子短语的安全性，而不是
keypair 文件本身，该文件以不安全的明文存储

BIP39 密码短语（留空表示不使用）：

已将新 keypair 写入 /Users/test/.config/solana/id.json
===========================================================================
公钥: 8dBTPrjnkXyuQK3KDt9wrZBfizEZijmmUQXVHpFbVwGT
===========================================================================
请保存此种子短语和您的 BIP39 密码短语以恢复您的新 keypair：
cream bleak tortoise ocean nasty game gift forget fancy salon mimic amazing
===========================================================================
```

<Callout type="note">

如果您已经在默认位置保存了文件系统钱包，则此
命令**不会**覆盖它，除非您明确强制覆盖使用
`--force` 标志。

</Callout>

生成 keypair 后，您可以使用以下命令获取 keypair 的地址（公钥）：

```shell
solana address
```

</Step>
<Step>

### 空投 SOL

一旦您设置好了本地钱包，请请求 SOL 的空投以资助您的钱包。您需要 SOL 来支付交易费用和部署程序。

将您的集群设置为 devnet：

```shell
solana config set -ud
```

然后请求 devnet SOL 的空投：

```shell
solana airdrop 2
```

要检查钱包的 SOL 余额，请运行以下命令：

```shell
solana balance
```

<Callout>

`solana airdrop` 命令目前在 devnet 上每次请求的限制为 5 SOL。错误通常是由于限速造成的。

替代方案，您可以通过
[Solana Web Faucet](https://faucet.solana.com) 获取 devnet SOL。

</Callout>
</Step>
<Step>

### 运行本地验证器

Solana CLI 内置了
[test validator](https://docs.solanalabs.com/cli/examples/test-validator)。运行本地验证器将允许您在本地部署和测试程序。

在一个单独的终端中，运行以下命令以启动本地验证器：

```shell
solana-test-validator
```

请确保在运行命令之前将 Solana CLI 配置更新为 localhost。

```shell
solana config set -ul
```

</Step>
</Steps>
