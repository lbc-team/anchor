Program Derived Addresses (PDA) 是 Solana 开发中的一项功能，它允许你从预定义的输入（种子）和程序 ID 确定性地生成一个唯一的地址。

本节将介绍如何在 Anchor 程序中使用 PDA 的基本示例。

## Anchor PDA 约束

在 Anchor 程序中使用 PDA 时，通常使用 Anchor 的账户约束来定义生成 PDA 的种子。这些约束充当安全检查，以确保生成正确的地址。

用于定义 PDA 种子的约束包括：

- `seeds`：用于生成 PDA 的可选种子数组。种子可以是静态值或对账户数据的动态引用。
- `bump`：用于生成 PDA 的 bump seed。用于确保地址远离 Ed25519 曲线，并且是一个有效的 PDA。
- `seeds::program` -（可选）用于生成 PDA 地址的程序 ID。此约束仅在程序 ID 不是当前程序时使用。

<Callout type="info">
  `seeds` 和 `bump` 约束必须一起使用。
</Callout>

### 使用示例

以下是演示如何在 Anchor 程序中使用 PDA 约束的示例。

<Tabs items={['seeds', 'bump', 'seeds::program', 'init']}>
<Tab value="seeds">

`seeds` 约束指定了用于生成 PDA 的可选值。

#### 无可选种子

- 使用空数组 `[]` 来定义没有可选种子的 PDA。

```rust
#[derive(Accounts)]
pub struct InstructionAccounts<'info> {
    #[account(
        // [!code highlight]
        seeds = [],
        bump,
    )]
    pub pda_account: SystemAccount<'info>,
}
```

#### 单个静态种子

- 在 `seeds` 约束中指定可选种子。

```rust
#[derive(Accounts)]
pub struct InstructionAccounts<'info> {
    #[account(
        // [!code word:b"hello_world"]
        // [!code highlight]
        seeds = [b"hello_world"],
        bump,
    )]
    pub pda_account: SystemAccount<'info>,
}
```

#### 多个种子和账户引用

- 可以在 `seeds` 约束中指定多个种子。`seeds` 约束还可以引用其他账户地址或账户数据。

```rust
#[derive(Accounts)]
pub struct InstructionAccounts<'info> {
    pub signer: Signer<'info>,
    #[account(
        // [!code highlight]
        seeds = [b"hello_world", signer.key().as_ref()],
        bump,
    )]
    pub pda_account: SystemAccount<'info>,
}
```

上面的示例同时使用了一个静态种子 (`b"hello_world"`) 和一个动态种子（签名者的公钥）。

</Tab>
<Tab value="bump">

`bump` 约束指定了用于生成 PDA 的 bump seed。

#### 自动计算 Bump

当使用不带值的 `bump` 约束时，每次调用指令时都会自动计算 bump。

```rust
#[derive(Accounts)]
pub struct InstructionAccounts<'info> {
    #[account(
        seeds = [b"hello_world"],
        // [!code highlight]
        bump,
    )]
    pub pda_account: SystemAccount<'info>,
}
```

#### 指定 Bump 值

你可以显式提供 bump 值，这对于优化计算单元使用很有用。假定 PDA 账户已创建，并且 bump seed 存储在现有账户的字段中。

```rust
#[derive(Accounts)]
pub struct InstructionAccounts<'info> {
    #[account(
        seeds = [b"hello_world"],
        // [!code highlight]
        bump = pda_account.bump_seed,
    )]
    pub pda_account: Account<'info, CustomAccount>,
}

#[account]
pub struct CustomAccount {
    pub bump_seed: u8,
}
```

通过将 bump 值存储在账户数据中，程序无需重新计算它，从而节省了计算单元。保存的 bump 值可以存储在账户本身或另一个账户上。

</Tab>
<Tab value="seeds::program">

`seeds::program` 约束指定了用于生成 PDA 的程序 ID。此约束仅在从不同程序生成 PDA 时使用。

当你的指令需要与另一个程序创建的 PDA 账户交互时，使用此约束。

```rust
#[derive(Accounts)]
pub struct InstructionAccounts<'info> {
    #[account(
        seeds = [b"hello_world"],
        bump,
        // [!code word:other_program]
        // [!code highlight]
        seeds::program = other_program.key(),
    )]
    pub pda_account: SystemAccount<'info>,
    pub other_program: Program<'info, OtherProgram>,
}
```

</Tab>
<Tab value="init">

`init` 约束通常与 `seeds` 和 `bump` 一起使用，以创建地址为 PDA 的新账户。在底层，`init` 约束调用系统程序来创建账户。

```rust
#[derive(Accounts)]
pub struct InstructionAccounts<'info> {
    #[account(mut)]
    pub signer: Signer<'info>,
    #[account(
        // [!code word:init]
        // [!code highlight:3]
        init,
        payer = signer,
        space = 8 + 1,
        seeds = [b"hello_world", signer.key().as_ref()],
        bump,
    )]
    pub pda_account: Account<'info, CustomAccount>,
    pub system_program: Program<'info, System>,
}

#[account]
pub struct CustomAccount {
    pub bump_seed: u8,
}
```

<Callout type="info">
  `init` 约束必须与 `payer` 和 `space` 一起使用。`payer` 指定将支付账户创建费用的账户。`space` 指定为账户分配的字节数（包括 8 字节的 discriminator）。
</Callout>

</Tab>
</Tabs>

## IDL 中的 PDA 种子

在 `seeds` 约束中定义的 Program Derived Address (PDA) 种子包含在程序的 IDL 文件中。这使得 Anchor 客户端在构建指令时能够自动使用这些种子解析账户地址。

下面的示例展示了程序、IDL 和客户端之间的关系。

<Tabs items={['Program', 'IDL', 'Client']}>
<Tab value="Program">

下面的程序使用静态种子 (`b"hello_world"`) 和签名者的公钥作为动态种子来定义 `pda_account`。

```rust
use anchor_lang::prelude::*;

declare_id!("BZLiJ62bzRryYp9mRobz47uA66WDgtfTXhhgM25tJyx5");

#[program]
mod hello_anchor {
    use super::*;
    pub fn test_instruction(ctx: Context<InstructionAccounts>) -> Result<()> {
        msg!("PDA: {}", ctx.accounts.pda_account.key());
        Ok(())
    }
}

#[derive(Accounts)]
pub struct InstructionAccounts<'info> {
    // [!code word:signer]
    pub signer: Signer<'info>,
    #[account(
        // [!code highlight]
        seeds = [b"hello_world", signer.key().as_ref()],
        bump,
    )]
    pub pda_account: SystemAccount<'info>,
}
```

</Tab>
<Tab value="IDL">

程序的 IDL 文件包含了在 `seeds` 约束中定义的 PDA 种子。

- 将静态种子 `b"hello_world"` 转换为字节值。
- 动态种子包含对签名者账户的引用。


<Tab value="Client">

Anchor 客户端可以使用 IDL 文件自动解析 PDA 地址。

在下面的示例中，Anchor 自动使用提供者钱包作为签名者，并使用其公钥作为 PDA 生成的动态种子来解析 PDA 地址。这使得在构建指令时无需显式生成 PDA。

```ts {13}
import * as anchor from "@coral-xyz/anchor";
import { Program } from "@coral-xyz/anchor";
import { HelloAnchor } from "../target/types/hello_anchor";

describe("hello_anchor", () => {
  // Configure the client to use the local cluster.
  anchor.setProvider(anchor.AnchorProvider.env());

  const program = anchor.workspace.HelloAnchor as Program<HelloAnchor>;

  it("Is initialized!", async () => {
    // Account address is automatically resolved using the IDL
    const tx = await program.methods.testInstruction().rpc();
    console.log("Your transaction signature", tx);
  });
});
```

当指令被调用时，PDA 会按照程序指令中的定义打印到程序日志中。
